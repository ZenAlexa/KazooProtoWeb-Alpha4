1. 关键问题总览
================================================================================

🔴 P0 严重问题 (必须立即修复)
────────────────────────────────────────────────────────────────────────────
1. 全局变量泛滥 (13个全局变量)
   - window.app, window.configManager, window.ExpressiveFeatures 等
   - 导致无法进行单元测试
   - 内存泄漏风险
   - 修复时间: 3天 | 影响: 所有模块

2. 两套音频系统并存
   - audio-input.js (ScriptProcessor) vs audio-io.js (AudioWorklet)
   - 维护成本高,容易产生不一致的bug
   - 修复时间: 4天 | 影响: 核心音频处理

3. 错误处理不完整
   - 麦克风权限拒绝、Worklet加载失败、网络错误无处理
   - 应用可能崩溃或静默失败
   - 修复时间: 2天 | 影响: 初始化流程

🟠 P1 高问题 (需要立即处理)
────────────────────────────────────────────────────────────────────────────
1. 260处console日志未清理
   - 性能问题(每帧10+个console.log)
   - 浏览器控制台内存泄漏
   - 修复时间: 1-2天

2. 版本号管理混乱
   - package.json: 1.0.0 vs app-config.js: 1.0.3
   - Phase 2, 2.5, 2.7, 2.9, 2.10 标记混乱
   - 修复时间: 2小时

3. 硬编码的魔法数字(30+个)
   - Math.pow(brightness, 1.5) - 1.5是什么?
   - canvas.height * 0.8 - 为什么80%?
   - 修复时间: 4小时

🟡 P2 中等问题
────────────────────────────────────────────────────────────────────────────
1. 代码重复度高 (15-20%)
   - onAudioProcess() 和 handleWorkletPitchFrame() UI更新逻辑重复
   - validateConfig() 中buffer验证重复

2. 函数过长
   - _startWithAudioIO(): 85行
   - _initializeEngines(): 60行
   - continuous-synth.js initialize(): 200+行

3. 缺少类型检查
   - JavaScript无类型,难以追踪pitchFrame数据结构

方案A: 消除全局变量 (推荐)
──────────────────────────
// 当前 (反模式)
const synthesizerEngine = new SynthesizerEngine();
window.app = app;
this.currentEngine = synthesizerEngine;

// 改进 (依赖注入)
class KazooApp {
  constructor(engineFactory, configManager) {
    this.engineFactory = engineFactory;
    this.configManager = configManager;
  }
  
  async start() {
    const config = this.configManager.get();
    this.currentEngine = this.engineFactory.createContinuousEngine(config);
  }
}

const engineFactory = new EngineFactory();
const configManager = new ConfigManager();
const app = new KazooApp(engineFactory, configManager);
